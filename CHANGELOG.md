- **R127** (AIR-2379) — review follow-up (coordinator review of airbrx-gateway PR #261): `contrib/sessionState.js`'s Postgres SET reader now classifies `SET SESSION CHARACTERISTICS AS TRANSACTION <characteristics>` as `transaction:isolation_level` (value = the characteristics text, e.g. `"ISOLATION LEVEL REPEATABLE READ"`, `"READ ONLY, ISOLATION LEVEL SERIALIZABLE"`), the same shape `SET TRANSACTION …` already produced — it had fallen through the reader as `none`, which would have let a deferring caller treat a later plain `BEGIN` as READ COMMITTED and cache its SELECT under REPEATABLE READ.
- **R126** (AIR-2379) — prerequisite (Epic 14 follow-on, Ben 2026-10-28: autocommit-off clients wrap every SELECT in `BEGIN … COMMIT`, so the gateway must pair the BEGIN with the statement that follows and eat the matching COMMIT to cache anything): `contrib/sessionState.js` surfaces a `BEGIN`/`START TRANSACTION`'s transaction modes as the `transaction:begin` Effect's value (`BEGIN ISOLATION LEVEL REPEATABLE READ` → `"ISOLATION LEVEL REPEATABLE READ"`, `BEGIN ISOLATION LEVEL SERIALIZABLE, READ WRITE` → `"ISOLATION LEVEL SERIALIZABLE, READ WRITE"`, plain `BEGIN`/`BEGIN WORK`/`START TRANSACTION` → `null`), because a caller deciding whether a transaction is cache-equivalent to autocommit must know its isolation level: READ COMMITTED takes a fresh snapshot per statement, REPEATABLE READ / SERIALIZABLE pin it at the first statement.
- **R125** (AIR-2364) — review follow-ups (Epic 14; bissellator's review of airbrx-gateway PR #256 `d7e4f10`): `contrib/sessionState.js` classifies every transaction-control spelling as `transaction` — `START TRANSACTION` (upstream-faithful Alias misparse), `ABORT [WORK|TRANSACTION]` (bare Column / Alias / Command) and `END` inside a batch (`EndStatement`, where alone it is `Commit`) — so a caller's transaction-control fallback can no longer be bypassed by `START TRANSACTION; SET search_path = a` or `SET search_path = a; ABORT` (both folded sequentially and trusted the SET before); `SET SCHEMA` / `SET search_path =` with no value is `unknown` (`missing-value`) instead of a `set` whose null value became the label `path:null`; and the port gains `addLogSink`/`removeLogSink` (additive top-level export) so an embedder can route the parser's Command-fallback warnings to its own logger instead of `console.error`.
